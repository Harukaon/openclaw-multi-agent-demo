# OpenClaw 多 Agent 多群聊演示平台：管理员交接手册

## 1. 当前范围

当前交付是“可真实验收的协议与运行闭环”，不是公网产品 UI：

- Platform 保存 User、Agent、Group、Membership、Message、每 Agent/Group ACK 状态。
- Agent 注册生成一次性 token；数据库只保存 SHA-256 hash，创建响应之外不再显示 token。
- Agent 不会自动加入任何群组；管理员显式添加后才接收该群消息。
- 一个 Agent 只有一个 Platform WebSocket，但可属于多个 Group；每个 Group 使用独立的 OpenClaw session route。
- 已实现纯文本、Group-scoped seq、Mention 状态、断线 replay、Pause、Reset。
- 未实现媒体、语音、Poll、Thread UI、公网用户登录和成品前端；不要把当前 loopback 单机 API 当作公网管理面。

## 2. 今晚单机拓扑

目标主机：`feedmob2`。

| 服务 | Compose 服务 | 容器内端口 | 宿主机端口 |
|---|---|---:|---:|
| Platform | `feedmob-group-platform` | 8787 | `127.0.0.1:18788` |
| Agent A Gateway | `openclaw-agent-a` | 18789 | `127.0.0.1:18790` |
| Agent B Gateway | `openclaw-agent-b` | 18789 | `127.0.0.1:18791` |
| Agent C Gateway | `openclaw-agent-c` | 18789 | `127.0.0.1:18792` |

现有 `openclaw-cf` 的 `127.0.0.1:18789` 不动。三只 Agent 通过 Compose DNS 访问 `http://feedmob-group-platform:8787`，今晚不需要 DNS、HTTPS 或跨机端口。

部署文件：[`deploy/single-host/`](../deploy/single-host/)。

## 3. 外部构建

服务器不执行 `docker build`、`npm install` 或 TypeScript 编译。将 [`deploy/github-actions/build.yml`](../deploy/github-actions/build.yml) 放到仓库的 `.github/workflows/` 后，用 GitHub Actions 的 amd64 runner 构建并发布：

- `ghcr.io/<owner>/feedmob-openclaw-group-platform:latest`
- `ghcr.io/<owner>/feedmob-openclaw-group-chat:latest`

第二个镜像以现有 `ghcr.io/harukaon/feedmob-openclaw-cf:latest` 为基础，内置 Camofox 与本项目 Channel Plugin。发布后在单机 `.env` 中覆盖 `PLATFORM_IMAGE`、`OPENCLAW_GROUP_IMAGE`（若 owner 不是 `harukaon`）。

## 4. 首次单机配置

在服务器专用目录中执行，不要把填写后的文件回传：

```bash
cp .env.example .env
chmod 600 .env
# 编辑 .env，填写三个 Gateway token（Platform 演示 API 不启用 Admin token）

for agent in agent-a agent-b agent-c; do
  cp "config/$agent/openclaw.json.template" "config/$agent/openclaw.json"
done
```

临时模型只通过隐藏输入配置，不写入仓库：

```bash
read -rsp 'Temporary FeedMob API key: ' FEEDMOB_API_KEY; echo
export FEEDMOB_API_KEY
./configure-model.sh
unset FEEDMOB_API_KEY
```

该脚本为三个 Agent 写入同一个 FeedMob provider 和 `minimax-m3` 默认模型。API key 只存在服务器运行配置中，不会出现在本手册、测试报告或项目记忆。

先启动 Platform：

```bash
docker compose up -d feedmob-group-platform
curl -fsS http://127.0.0.1:18788/health
```

直接调用 `POST /api/agents` 创建三个 Agent。每个 Agent token 只保存到服务器 `.env`，不要复制到聊天记录或仓库。把返回的三个 Agent id/token 填入 `.env`，然后：

```bash
docker compose up -d openclaw-agent-a openclaw-agent-b openclaw-agent-c
docker compose ps
```

## 5. 创建 User、Group 和成员

演示环境的 Platform API 不启用 Admin token，下面的 `ownerId`、`agentId` 使用实际 API 返回值；示例不包含任何真实密钥。

```bash
BASE=http://127.0.0.1:18788

curl -fsS -X POST "$BASE/api/users" -H 'content-type: application/json' \
  -d '{"username":"alice","displayName":"Alice"}'

curl -fsS -X POST "$BASE/api/groups" -H 'content-type: application/json' \
  -d '{"name":"演示群 A","ownerId":"<alice-id>"}'

curl -fsS -X POST "$BASE/api/groups/<group-id>/members" -H 'content-type: application/json' \
  -d '{"actorId":"<alice-id>","memberType":"agent","memberId":"<agent-a-id>"}'
```

同一个 Agent 可被加入多个 Group；只有显式 `group_members` 记录存在时才会接收消息。每个用户 turn 由 Platform 按 Agent 加入顺序串行投递：先给 Agent A，收到 ACK 后把用户原话及 A 的可见回复累计注入给 Agent B，以此类推。Platform 会按 Agent 注入 `SELF`、`DIRECT`、`OTHER` 或 `NONE` 提示；没有有效贡献时让 Agent 输出精确 `NO_REPLY`，插件会静默，不写回群里。整个机制只改 Platform/插件，不改 OpenClaw。

## 6. 验收命令

```bash
# Platform API/WS 验收：创建临时资源，不输出 token
node ../../tests/smoke-platform.mjs http://127.0.0.1:18788

# 资源护栏
docker stats --no-stream
free -h
```

烟测覆盖：Agent A 属于两个 Group、Agent B 只属于一个 Group；两个 Group 的 seq 独立；管线不越权；A ACK 后 B 才收到包含 A 回复的累计提示词；精确 `NO_REPLY` 不产生群消息。

真实 OpenClaw 演示时，在对应 Gateway 的会话中使用简单提示，例如“只回复 GROUP-A-OK”，再在两个 Group 中分别发送不同标记，检查回复不会串群。不要用复杂工具调用替代首轮链路验证。

## 7. 内存护栏和迁移顺序

当前实测快照：feedmob2 `MemAvailable` 约 `3.7GiB`，feedmob3 约 `5.8GiB`；feedmob2 已有服务中 Hermes 占用较大，因此不把缓存当作永久余量。

Compose 限制：

- Platform：`384MiB` 上限、`256MiB` 保留。
- 每只 OpenClaw+Camofox：`768MiB` 上限、`512MiB` 保留。
- 启动后宿主机必须至少保留 `500MiB` 可用内存，目标 `1GiB`。

低于门槛时：

```bash
docker compose stop openclaw-agent-c
docker stats --no-stream
free -h
```

不要为了 demo 停现有 OpenShip、Hermes 或 `openclaw-cf`。如果仍不足，把 Agent C 迁移到 F3；迁移只改它的 `FEEDMOB_GROUP_SERVER_URL` 和 Gateway 端口，不改变 Platform 协议或 Agent id/token。

## 8. 演练结束清理

```bash
docker compose stop openclaw-agent-a openclaw-agent-b openclaw-agent-c
for agent in agent-a agent-b agent-c; do
  jq 'del(.models.providers.feedmob.apiKey)' "config/$agent/openclaw.json" > "config/$agent/openclaw.json.clean"
  mv "config/$agent/openclaw.json.clean" "config/$agent/openclaw.json"
done
rm -f .env
```

若连烟测数据也不要保留，再删除 `platform-data/`；若需要保留群聊事实记录，则只删 key 和运行 token，保留 Platform SQLite。最终检查：仓库、报告、shell 输出和交接文档中不得出现 API key、Agent token 或 Gateway token。
